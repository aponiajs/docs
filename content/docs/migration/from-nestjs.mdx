AponiaJS borrows structural vocabulary from NestJS, so most of a port is
mechanical. This page puts the two versions of each construct next to each
other. If you are still choosing rather than porting, read
[AponiaJS vs NestJS](/docs/compare/nestjs) first.

## What ports and what does not

| Nest concept | AponiaJS `0.6.0-alpha.18` |
| --- | --- |
| Modules | Implemented with imports, controllers, providers, and exports. |
| Singleton providers | Implemented. |
| Class/value/factory/alias providers | Implemented synchronously. |
| Decorated controllers | Implemented for all seven HTTP methods. |
| Request parameter decorators | Implemented, including named selection. |
| Validation | Implemented as route schemas and `@Validation()` model classes, not pipes. |
| Gateways | Implemented over native Elysia WebSockets, without Socket.IO semantics. |
| Exception filters | Not implemented; throw `httpErrors.*` for Problem Details responses. |
| Platform adapter | Elysia only. |
| Guards/interceptors/filters/middleware runtime | Not implemented. |
| Provider scopes and lifecycle hooks | Not implemented. |
| Testing module and overrides | Not implemented. |
| OpenAPI/auth/microservices | Not implemented. |

## Packages

The decorator names survive the port. The imports do not.

<CodeCompare>
<CodeCompareSide label="NestJS" note="Core package plus a platform adapter.">

```ts
import { Body, Controller, Get, Injectable, Module, Param, Post } from "@nestjs/common";
import { NestFactory } from "@nestjs/core";
```

</CodeCompareSide>
<CodeCompareSide label="AponiaJS" variant="after" note="Decorators from common, the factory from the platform.">

```ts
import { Body, Controller, Get, Injectable, Module, Param, Post } from "@aponiajs/common";
import { AponiaFactory } from "@aponiajs/platform-elysia";
```

</CodeCompareSide>
</CodeCompare>

```bash
bun add @aponiajs/common@alpha @aponiajs/platform-elysia@alpha elysia@^1.4.29
```

## Bootstrap

<CodeCompare>
<CodeCompareSide label="NestJS" note="The factory chooses an HTTP adapter.">

```ts
async function bootstrap() {

  await app.listen(3000);
}

bootstrap();
```

</CodeCompareSide>
<CodeCompareSide label="AponiaJS" variant="after" note="Top-level await; the platform is always Elysia.">

```ts
const application = await AponiaFactory.create(AppModule);
await application.listen(3000);
```

</CodeCompareSide>
</CodeCompare>

## Modules

Identical, minus the features that have no runtime behind them yet.

<CodeCompare>
<CodeCompareSide label="NestJS">

```ts
@Module({
  imports: [DatabaseModule],
  controllers: [UserController],
  providers: [UserService],
  exports: [UserService],
})
export class UserModule {}
```

</CodeCompareSide>
<CodeCompareSide label="AponiaJS" variant="after" note="Same four keys, validated at startup.">

```ts
@Module({
  imports: [DatabaseModule],
  controllers: [UserController],
  providers: [UserService],
  exports: [UserService],
})
export class UserModule {}
```

</CodeCompareSide>
</CodeCompare>

A provider a module never exported is a bootstrap error with a diagnostic
rather than a runtime failure. See [visibility](/docs/essentials/visibility).

## Controllers

<CodeCompare>
<CodeCompareSide label="NestJS">

```ts
@Controller("users")
export class UserController {
  constructor(private readonly userService: UserService) {}

  @Get(":id")
  findOne(@Param("id") id: string) {
    return this.userService.findOne(id);
  }

  @Post()
  create(@Body() body: CreateUserDto) {
    return this.userService.create(body);
  }
}
```

</CodeCompareSide>
<CodeCompareSide label="AponiaJS" variant="after" note="Same decorators; the body type is annotated, not inferred from a DTO class.">

```ts
@Controller("users")
export class UserController {
  constructor(private readonly userService: UserService) {}

  @Get(":id")
  findOne(@Param("id") id: string) {
    return this.userService.findOne(id);
  }

  @Post()
  create(@Body() body: CreateUser) {
    return this.userService.create(body);
  }
}
```

</CodeCompareSide>
</CodeCompare>

Two differences that bite during a port:

- there is no `@Injectable()`-driven metadata for method decorators.
  `@Injectable()` exists only so TypeScript emits constructor parameter types;
- handler parameter types come from your annotations, not from schema
  inference, so keep the schema in a `const` and derive with `z.infer` or
  `Static<typeof …>`.

## Providers

<CodeCompare>
<CodeCompareSide label="NestJS" note="Scope is a decorator option.">

```ts
@Injectable({ scope: Scope.DEFAULT })
export class UserService {
  findOne(id: string) {
    return { id };
  }
}
```

</CodeCompareSide>
<CodeCompareSide label="AponiaJS" variant="after" note="No scopes exist. Every provider is a startup singleton.">

```ts
@Injectable()
export class UserService {
  findOne(id: string) {
    return { id };
  }
}
```

</CodeCompareSide>
</CodeCompare>

Non-class dependencies use an explicit token on both sides.

<CodeCompare>
<CodeCompareSide label="NestJS">

```ts
@Module({
  providers: [{ provide: "CONFIG", useValue: { url: "…" } }],
})
export class ConfigModule {}

constructor(@Inject("CONFIG") private readonly config: Config) {}
```

</CodeCompareSide>
<CodeCompareSide label="AponiaJS" variant="after" note="Same shape; see tokens and injection.">

```ts
@Module({
  providers: [{ provide: "CONFIG", useValue: { url: "…" } }],
})
export class ConfigModule {}

constructor(@Inject("CONFIG") private readonly config: Config) {}
```

</CodeCompareSide>
</CodeCompare>

Async factory providers do not port — `useFactory` is synchronous. See
[providers](/docs/essentials/providers) and
[tokens](/docs/essentials/tokens).

## Validation replaces pipes

This is the largest rewrite in a typical port: `class-validator` DTO classes
become schemas attached to the route.

<CodeCompare>
<CodeCompareSide label="NestJS" note="A DTO class, decorators, and a global ValidationPipe.">

```ts
export class CreateUserDto {
  @IsString()
  @MinLength(2)
  name: string;
}

app.useGlobalPipes(new ValidationPipe());

@Post()
create(@Body() body: CreateUserDto) {
  return body;
}
```

</CodeCompareSide>
<CodeCompareSide label="AponiaJS" variant="after" note="A schema on the decorator, rejected before the handler runs.">

```ts
const createUser = {
  body: z.object({ name: z.string().min(2) }),
};

@Post("/", createUser)
create(@Body() body: z.infer<(typeof createUser)["body"]>) {
  return body;
}
```

</CodeCompareSide>
</CodeCompare>

Any [Standard Schema](https://standardschema.dev) validator works — Zod,
ArkType, Valibot — as do TypeBox and Elysia's `t`. A rejected request answers
`422`. If you prefer the DTO-shaped arrangement, `@Validation()` model classes
keep the schema in a named class; see
[validation](/docs/essentials/validation).

## Errors replace exception filters

<CodeCompare>
<CodeCompareSide label="NestJS" note="HttpException, optionally reshaped by a filter.">

```ts
throw new NotFoundException("User not found");

@Catch(HttpException)
export class HttpFilter implements ExceptionFilter {
  catch(exception: HttpException, host: ArgumentsHost) {
    // reshape the response
  }
}
```

</CodeCompareSide>
<CodeCompareSide label="AponiaJS" variant="after" note="RFC 9457 Problem Details, no filter layer.">

```ts
throw httpErrors.notFound("User not found");

// {
//   "type": "about:blank",
//   "title": "Not Found",
//   "status": 404,
//   "detail": "User not found"
// }
```

</CodeCompareSide>
</CodeCompare>

There is no exception filter runtime. The response shape is the framework's,
documented in [errors](/docs/essentials/errors).

## Gateways

<CodeCompare>
<CodeCompareSide label="NestJS" note="Socket.IO semantics by default.">

```ts
@WebSocketGateway()
export class EventsGateway {
  @SubscribeMessage("events")
  handle(@MessageBody() data: string) {
    return { event: "events", data };
  }
}
```

</CodeCompareSide>
<CodeCompareSide label="AponiaJS" variant="after" note="Native Elysia and Bun sockets, same decorator names.">

```ts
@WebSocketGateway()
export class EventsGateway {
  @SubscribeMessage("events")
  handle(@MessageBody() data: string) {
    return { event: "events", data };
  }
}
```

</CodeCompareSide>
</CodeCompare>

The decorators match; the transport does not. There are no rooms, namespaces,
acknowledgements, or Socket.IO clients — messages are a plain
`{ event, data }` envelope over a native WebSocket. See
[websockets](/docs/essentials/websockets).

## Guards, interceptors, and middleware

These have no equivalent. Nothing ports; the behaviour is rewritten as an
Elysia hook.

<CodeCompare>
<CodeCompareSide label="NestJS" note="Four extension points around the handler.">

```ts
@UseGuards(AuthGuard)
@UseInterceptors(LoggingInterceptor)
@Get()
findAll() {
  return this.service.findAll();
}
```

</CodeCompareSide>
<CodeCompareSide label="AponiaJS" variant="after" note="An Elysia hook installed through native access.">

```ts
const application = await AponiaFactory.create(AppModule, {
  configureNative: (elysia) =>
    elysia.onBeforeHandle(({ request, status }) => {
      if (!request.headers.get("authorization")) return status(401);
    }),
});
```

</CodeCompareSide>
</CodeCompare>

The hook is not part of the module graph and cannot be applied per controller
method. Details in [native access](/docs/elysia/native-access) and
[plugin modules](/docs/elysia/plugin-modules).
